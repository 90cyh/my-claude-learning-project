## 1. 设计原则

1. **范围对齐 PRD V1.0.1**：本地账户（5.9）+ 支出记账（5.1~5.3）+ 统计（5.4）+ 导出（5.5）；收入、资金账户、预算按 PRD 7.3/7.4 **表结构一次建齐**（应用层 V1.1 启用），避免将来变更表结构。
2. **账户隔离**：所有业务表带 `user_id` 外键（PRD 7.5），配合索引 `(user_id, date)` 保证隔离查询性能。
3. **金额口径**：恒为正数、方向由 `type` 决定（PRD 7.1）；`DECIMAL(10,2)` 精确小数——上限 99,999,999.99 恰好 10 位（PRD 5.1），并彻底规避浮点累加误差。
4. **删除不丢数据**：所有删除行为严格映射 PRD 规则（见第 5 节删除策略表）。
5. **分类为全局种子数据**：9 个支出 + 5 个收入分类内置（PRD 5.2），跨用户共享；资金账户为用户注册时按模板创建的**用户级数据**（PRD 5.7）。

## 2. ER 关系图

```
user（本地账户）
 ├── 1:n transaction（交易）── n:1 category（分类，自关联二级）
 │                    └── n:1 account（资金账户，可空 = 未分配）
 ├── 1:n account（资金账户）
 ├── 1:n budget（预算，category_id 为空 = 总预算）
 ├── 1:n session（会话，可选表）
 └── 1:n user_setting（偏好设置，key-value）

category 自关联：parent_id → category.id（NULL = 一级分类）
```

## 3. 表清单

| 表名 | 对应 PRD | 说明 |
| --- | --- | --- |
| `user` | 7.5 / 5.9 | 本地账户：UUID 主键、密码哈希+盐（永不明文） |
| `session` | 7.5 | 会话（可选表：DB 落地会话时使用；localStorage 方案可不用） |
| `user_setting` | 7.5 | 用户偏好（主题等），key-value 结构（`key` 为保留字，须反引号） |
| `category` | 7.2 / 5.2 | 两级分类，含图标与色值；`is_active` 逻辑删除 |
| `transaction` | 7.1 / 5.1 | 交易流水（核心表）；恒正金额、原生 DATE 类型 |
| `account` | 7.3 / 5.7 | 资金账户（V1.1）；余额实时计算不落库 |
| `budget` | 7.4 / 5.6 | 月度预算（V1.1）；`category_id` 为空 = 总预算 |

## 4. 索引设计

| 索引 | 服务场景 | PRD 依据 |
| --- | --- | --- |
| `idx_txn_user_date (user_id, date)` | 明细页按月/按日查询、月度汇总 | 7.1 索引建议 |
| `idx_txn_user_cat_date (user_id, category_id, date)` | 分类占比、分类下钻 | 7.1 索引建议 |
| `idx_txn_account (account_id)` | 资金账户余额实时计算（V1.1） | 5.7 规则 2 |
| `idx_category_parent (parent_id)` | 二级分类树加载 | 5.2 |
| `idx_budget_user (user_id)` | 预算页加载当前用户预算 | 5.6 |

> 外键列 InnoDB 会自动补索引；显式索引以查询场景为主，外键复用其最左前缀。

## 5. 删除策略（PRD 规则 → 数据库落地）

| PRD 规则 | 数据库落地 |
| --- | --- |
| 分类删除 → 流水归入「其他」，不允许物理丢失（5.2 规则 3） | 一级分类被交易引用时 `ON DELETE RESTRICT`，**必须由应用先把流水改指「其他」分类再删除** |
| 二级分类为可选（5.1） | `subcategory_id ON DELETE SET NULL` |
| 资金账户删除 → 流水转「未分配」（5.7 规则 4） | `transaction.account_id ON DELETE SET NULL` |
| 本地账户重置 = 删除全部数据（5.9 重置账户） | `user` 删除 → 交易/预算/资金账户/会话/偏好全部 `ON DELETE CASCADE` |
| 预算所属分类删除 | `budget.category_id ON DELETE CASCADE` |

## 7. 数据完整性约束（CHECK 一览）

| 约束 | 位置 | PRD 依据 |
| --- | --- | --- |
| 用户名 3~20 **字符**（`CHAR_LENGTH`，非字节） | `user.username` | 5.9 注册规则 |
| 交易类型仅 `expense`/`income` | `transaction.type` | 7.1 |
| 金额 > 0 且 ≤ 99,999,999.99（`DECIMAL(10,2)`） | `transaction.amount` | 5.1 / 7.1 |
| 日期为原生 `DATE` 类型（无需格式校验） | `transaction.date` | 7.1 |
| 备注 ≤ 50 字符 | `transaction.note` | 5.1 |
| 分类类型仅 `expense`/`income` | `category.type` | 7.2 |
| 触发器：交易类型与分类类型/层级一致性（`IF + SIGNAL`） | `trg_txn_category_consistency` | 5.2 规则 1 |
| 触发器：更新时间自动维护（`BEFORE UPDATE SET NEW`） | `trg_txn_touch_updated` | 7.1 `updated_at` |

## 8. SQLite → MySQL 差异对照（本轮适配记录）

| # | SQLite 原写法 | MySQL 改为 | 原因 |
| --- | --- | --- | --- |
| 1 | `id TEXT PRIMARY KEY` | `VARCHAR(36) PRIMARY KEY` | MySQL 的 TEXT 不能作主键/索引 |
| 2 | `AUTOINCREMENT` + `PRAGMA foreign_keys` | `AUTO_INCREMENT`；去掉 PRAGMA；**建表顺序按外键依赖重排** | MySQL 要求被引用表先建 |
| 3 | `amount REAL` | `DECIMAL(10,2)` | 精确小数，落地原第 8 节浮点误差建议 |
| 4 | `date TEXT + GLOB 校验` | 原生 `DATE` 类型 | MySQL 有原生日期类型，无需字符串校验 |
| 5 | `strftime('%Y-%m-%dT%H:%M:%fZ','now')` 默认值 | `DATETIME(3) DEFAULT CURRENT_TIMESTAMP(3)` | MySQL 原生毫秒时间戳 |
| 6 | `IS NOT` / `RAISE(ABORT)` / WHEN 子句 | `IF ... THEN SIGNAL SQLSTATE '45000'` + `DELIMITER`；updated_at 改 `BEFORE UPDATE SET NEW` | 触发器语法完全不同；AFTER 阶段不可改本行 |
| 7 | `INSERT OR IGNORE` | `INSERT IGNORE` | MySQL 语法 |
| 8 | `length()` 字符计数 | `CHAR_LENGTH()` | MySQL `LENGTH()` 按字节，中文用户名会误判 |
| 9 | — | `key` 保留字加反引号 | MySQL 保留字 |
| 10 | — | 全表 `ENGINE=InnoDB utf8mb4` | 分类图标含 emoji，utf8 会插入失败 |

## 9. 使用方法

```bash
# 注意 --default-character-set=utf8mb4：保证 emoji 图标种子数据正常插入
mysql --default-character-set=utf8mb4 -u root -p < 简记数据库初始化脚本.sql
# 验证：
mysql -u root -p -e "SELECT type, COUNT(*) FROM jianji.category GROUP BY type;"
# 期望：expense=39（9 一级 + 30 二级）, income=5
```

种子数据说明：分类（id 1~14 及二级）为全局数据，脚本内置；资金账户为用户级数据，**用户注册成功后由应用执行**（模板见脚本第 6 节注释）。脚本可重复执行（`INSERT IGNORE` + 显式主键 + `CREATE TABLE IF NOT EXISTS`）。触发器使用了 `DELIMITER`，适用于 mysql 命令行客户端；部分 GUI 工具需分段执行或关闭分隔符切换。
